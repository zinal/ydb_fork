# Replication нагрузка

Нагрузка проверяет [асинхронную репликацию](../../concepts/async-replication.md) строковых таблиц. Команда создаёт исходные таблицы, заполняет их и затем выполняет многотабличные транзакции. Записи на базе-источнике образуют поток изменений, который читает репликация.

Пользователь создаёт экземпляр асинхронной репликации после начального заполнения и до запуска записи. Начальные строки попадают в реплику при [первоначальном сканировании](../../concepts/async-replication.md#initial-scan). Транзакции `run` дают [репликацию изменений](../../concepts/async-replication.md#replication-of-changes). Команда пишет только в базу-источник.

## Порядок запуска {#flow}

```bash
{{ ydb-cli }} workload replication init [options...]
{{ ydb-cli }} workload replication import [options...]
# здесь пользователь создаёт экземпляр асинхронной репликации
{{ ydb-cli }} workload replication run [options...]
{{ ydb-cli }} workload replication clean [options...]
```

1. `init` создаёт каталог и пустые строковые таблицы.
2. `import` записывает в каждую таблицу ровно **Q** строк. Q задаётся параметром `--rows`.
3. Пользователь создаёт экземпляр асинхронной репликации для этого каталога выражением [CREATE ASYNC REPLICATION](../../yql/reference/syntax/create-async-replication.md).
4. `run` в течение заданного времени выполняет транзакции записи.
5. `clean` удаляет таблицы нагрузки и их каталог. Перед `clean` пользователь удаляет экземпляр репликации. Пока репликация удерживает потоки изменений этих таблиц, удаление может завершиться ошибкой сервера.

{% note info %}

В каталоге `--path` должны лежать только таблицы этой нагрузки. Репликация каталога забирает все строковые таблицы, которые есть в нём на момент создания экземпляра.

{% endnote %}

## Схема таблиц {#schema}

Все таблицы — строковые. Они создаются в каталоге `--path` (по умолчанию `replication`). Вторичные индексы, сжатие и настройки партиционирования описаны ниже.

Колонки первичного ключа и `seqno` объявляются `NOT NULL`. Остальные колонки допускают `NULL`. При вставке в `import` и в `run` с вероятностью 10% одно случайно выбранное поле значения, кроме `seqno`, записывается как `NULL`. В `UPDATE` с вероятностью 1% как `NULL` записывается одно из присваиваемых значений, кроме `seqno`. Если в `UPDATE` нет колонок, кроме `seqno`, пустое значение не записывается.

В первичный ключ строковой таблицы можно поставить сравнимый тип, который хранилище принимает в колонке. В этой нагрузке используются типы из таблиц ниже. Среди них есть `Interval` и `Interval64`: для обоих задано сравнение ключей, и таблица с `Interval` в первичном ключе создаётся. Типы `TzDate`, `TzDatetime`, `TzTimestamp`, `TzDate32`, `TzDatetime64` и `TzTimestamp64` в колонках строковых таблиц не хранятся, поэтому в схеме их нет. `Float`, `Double`, `Json`, `JsonDocument` и `Yson` стоят только в колонках значений. `Uuid` в первичном ключе требует одноимённую возможность сервера; в конфигурации по умолчанию она включена. Хранилище принимает в ключе также `DyNumber` и сравнимые типы PostgreSQL, но колонок этих типов в схеме нет.

Таблицы делятся на обычные и широкие. Обычная таблица хранит узкие значения. В `pk_bool` и `pk_decimal_narrow` по 11 колонок, в остальных обычных таблицах — по 10. Колонки типов `Utf8`, `String`, `Json`, `JsonDocument` и `Yson` в обычной таблице заполнены узко. Широкая таблица состоит из 30 колонок разных типов, одной текстовой колонки среднего заполнения и одной текстовой колонки широкого заполнения.

### Номер строки {#row-number}

У каждой строки есть номер `n`: целое число от 0 и выше. После `import` в таблице лежат номера `0 .. Q-1`. Команда `run` дописывает следующие номера. Первичный ключ запоминается при вставке и потом не меняется. Во всех таблицах, кроме `pk_bool` и `pk_decimal_narrow`, ключ вычисляется из `n`, и разным номерам соответствуют разные ключи. У этих двух таблиц первая компонента — хеш `seqno` вставки, а `seq` равен `n`, поэтому разные номера тоже дают разные ключи.

### Поле seqno {#seqno}

В каждой таблице есть колонка `seqno` типа `Uint64 NOT NULL`. В первичный ключ она не входит. Колонка `seq` композитного ключа хранит номер строки `n`. Колонка `seqno` хранит номер операции, общий для всех таблиц одной транзакции. При выборе поля, которое записывается как `NULL`, колонка `seqno` не рассматривается.

Все строки, которые одна транзакция вставляет или изменяет, получают в `seqno` один и тот же номер. От этого же номера считается `seqno_hash`.

Номер операции назначает атомарный счётчик внутри процесса команды. Счётчик увеличивается в момент формирования транзакции. При повторе транзакции номер не меняется.

Во время команды `import` номер операции равен 0, и счётчик не увеличивается.

В начале команды `run` счётчик становится равным текущему времени Unix в микросекундах: это число микросекунд UTC, прошедших с 1970-01-01. Первая транзакция запуска получает это значение, а каждая следующая новая транзакция — на единицу больше. Следующий запуск `run` снова ставит счётчик по времени своего старта.

### Композитный ключ узкого типа {#composite-key}

Если у типа меньше 2^32 различных значений, одной колонки этого типа недостаточно: после исчерпания диапазона новую строку вставить нельзя. У `Int8`, `Uint8`, `Int16`, `Uint16` и `Date` первичный ключ — `(pk <тип>, seq Uint64)`. Второй компонент всегда имеет тип `Uint64` и равен номеру `n`. Первая колонка пробегает весь диапазон типа: `pk` получается как `n % <размер диапазона>`.

К узким типам относятся `Bool` (2 значения), `Int8` и `Uint8` (256), `Int16` и `Uint16` (65536), `Date` (дни от 1970-01-01 до 2105-12-31, 49673 значения) и `Decimal(1, 0)` (значения от −9 до 9).

У `Bool` и `Decimal(1, 0)` перед этим ключом стоит колонка `seqno_hash` типа `Uint64 NOT NULL`. Первичный ключ этих двух таблиц — `(seqno_hash, pk <тип>, seq Uint64)`. В `seqno_hash` записывается хеш номера `seqno` той транзакции, которая вставила строку. Значение `pk` получается как `n % <размер диапазона>`, а `seq` равен `n`.

Хеш считается в беззнаковой 64-битной арифметике. Сложение и умножение берутся по модулю 2^64, сдвиг вправо логический:

```
x = seqno + 0x9e3779b97f4a7c15
x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9
x = (x ^ (x >> 27)) * 0x94d049bb133111eb
seqno_hash = x ^ (x >> 31)
```

Команда `import` записывает в `seqno` ноль, поэтому у всех начальных строк `pk_bool` и `pk_decimal_narrow` один и тот же `seqno_hash` — хеш нуля. Каждая новая транзакция `run` получает свой `seqno`, и её вставки в эти две таблицы получают хеш этого номера. Позднейшая запись в колонку `seqno` не меняет `seqno_hash`: там остаётся хеш, посчитанный при вставке. Условие `WHERE` при изменении сравнивает именно этот сохранённый хеш. В начале `run` команда читает `SELECT seq, seqno_hash` и запоминает хеш каждого уже записанного номера. После успешной вставки в том же запуске к этой памяти добавляется хеш `seqno` новых номеров. Колонка `seqno_hash` во вторичные индексы не входит.

Остальные ключевые типы записаны одной колонкой. В обычных таблицах она называется `pk`, в широких — `id`. Значение ключа получается обратимым перемешиванием номера `n` по допустимому диапазону типа, поэтому соседние номера попадают в разные участки порядка ключа.

### Обычные таблицы {#ordinary-tables}

Колонка `seq` есть только у композитного ключа и хранит номер строки. Колонка `seqno` есть у всех таблиц и хранит номер операции. Остальные колонки одной таблицы имеют разные типы. `Decimal(22, 9)` — штатная параметризация. `Decimal(1, 0)` — один десятичный разряд и нулевой масштаб. `Decimal(35, 0)` — точность 35 и нулевой масштаб. `String` — двоичный ключ (`Bytes` — то же тип). `Utf8` — текстовый ключ (`Text` — то же тип).

Двоичный и текстовый ключи — это криптографический хеш номера, а не его текстовая запись. Порядок таких ключей в таблице не совпадает с порядком номеров.

Разворот битов переставляет биты номера в обратном порядке: бит `i` результата равен биту `w − 1 − i` исходного номера. Для `Int32` и `Uint32` берётся `w = 32`, и номер должен быть меньше 2^32. Полученная битовая строка `Int32` читается как знаковое число. Для `Int64`, `Uint64`, колонки `id` широкой таблицы и `Decimal(35, 0)` берётся `w = 64`. У `Decimal(35, 0)` та же строка читается как неотрицательное целое.

Перемешивание по целочисленному диапазону `[lo, hi]` включительно:

```
span = hi − lo + 1
A — наименьшее нечётное положительное целое, взаимно простое со span
значение = lo + ((n * A) mod span)
```

Номер `n` должен быть меньше `span`. Множители для этих диапазонов:

| Тип | `lo` | `hi` | `A` |
| --- | --- | --- | --- |
| `Date32` | −53375809 | 53375807 | 3 |
| `Datetime` | 0 | `86400 * 49673 − 1` | 7 |
| `Datetime64` | −4611669897600 | 4611669811199 | 11 |
| `Timestamp` | 0 | `86400000000 * 49673 − 1` | 7 |
| `Timestamp64` | −4611669897600000000 | 4611669811199999999 | 11 |
| `Interval` | `−(86400000000 * 49673 − 1)` | `86400000000 * 49673 − 1` | 3 |
| `Interval64` | −9223339708799999999 | 9223339708799999999 | 3 |
| целая часть `Decimal(22, 9)` | 0 | `10^13 − 1` | 3 |

У `Uuid` старшие 8 байт — тот же хеш, что и у `seqno_hash`, посчитанный от номера `n` и записанный в порядке big-endian. Младшие 8 байт — сам номер `n` в порядке big-endian.

### Заполнение текстовых колонок {#text-size}

Текстовыми здесь считаются типы `Utf8`, `String`, `Json`, `JsonDocument` и `Yson`.

| Класс | Размер |
| --- | --- |
| узкий | от 0 до 100 байт включительно |
| средний | от 100 до 500 байт включительно, длина случайная |
| широкий | от 1000 до 5000 байт включительно, длина случайная |

Размер считается так:

* Для `Utf8` считается число байт текста. Генератор берёт фрагмент псевдотекста TPC-H: слова и знаки препинания из словаря `dists.dss`. Текст состоит из печатного ASCII, поэтому число байт совпадает с числом символов.
* Для `String` считается число байт. Байты случайные, допустима любая последовательность.
* Для `Json`, `JsonDocument` и `Yson` считается число байт текста, который клиент передаёт параметром. Документ корректный. В узком классе нижняя граница — длина самого короткого корректного значения: 2 байта (`{}`) у `Json` и `JsonDocument`, 1 байт (`#`) у `Yson`. В значениях длиннее коротких литералов, начиная с `{"v":"…"}` у `Json` и `{v="…"}` у `Yson`, внутри поля лежит тот же фрагмент псевдотекста TPC-H. Колонки `c_medium` и `c_wide` типа `JsonDocument` получают текст того же размера, что `Json` этого класса. Сервер хранит `JsonDocument` в бинарном виде, поэтому размер на диске может отличаться от размера текста.

В узкий класс для `String` и `Utf8` входит и пустое значение.

В каталоге 28 таблиц: 23 обычные и 5 широких.

## Индексы, сжатие и партиционирование {#indexes}

У каждой создаваемой таблицы включено сжатие группы колонок `default`. В этой группе лежат все колонки таблицы:

```yql
FAMILY default (COMPRESSION='lz4')
```

Вторичный индекс копирует семейство `default` таблицы, поэтому его данные тоже сжимаются lz4.

На колонку `seqno` каждой таблицы создаётся синхронный вторичный индекс `seqno_idx`:

```yql
INDEX seqno_idx GLOBAL SYNC ON (seqno)
```

На колонку `seq` создаётся такой же индекс `seq_idx`. Колонка `seq` есть только у таблиц с композитным ключом: `pk_bool`, `pk_int8`, `pk_uint8`, `pk_int16`, `pk_uint16`, `pk_date` и `pk_decimal_narrow`. У остальных таблиц индекса по `seq` нет.

Для каждой таблицы и для каждого из этих индексов включено автоматическое партиционирование по размеру и по нагрузке. Минимальное и максимальное число партиций задаётся параметрами `init`. По умолчанию это 1000 и 1100:

```yql
AUTO_PARTITIONING_BY_SIZE = ENABLED,
AUTO_PARTITIONING_BY_LOAD = ENABLED,
AUTO_PARTITIONING_MIN_PARTITIONS_COUNT = 1000,
AUTO_PARTITIONING_MAX_PARTITIONS_COUNT = 1100
```

Для таблицы эти параметры задаются в секции `WITH` при создании. Таблица создаётся с одной партицией: команда не задаёт начальные границы. Затем автоматическое партиционирование доводит число партиций до заданного минимума и не даёт ему превысить максимум.

Задать параметры партиционирования прямо при создании индекса нельзя. Команда `init` создаёт индекс, а затем выполняет `ALTER TABLE … ALTER INDEX … SET` с теми же четырьмя параметрами. Индексы `seqno_idx` и `seq_idx` строятся по колонкам `seqno` и `seq` и тоже создаются без начальных границ.

Если минимум больше максимума, `init` завершается ошибкой параметра и таблицы не создаёт.

## Начальное заполнение {#import}

Команда `import` вставляет в каждую таблицу строки с номерами `0 .. Q−1`. Ключ строки вычисляется по таблице выше. У каждой строки `seqno` равен 0. С вероятностью 10% одно из остальных полей значения остаётся `NULL`. У `pk_bool` и `pk_decimal_narrow` колонка `seqno_hash` равна хешу нуля.

Строки записываются пачками. В одной пачке не больше `--batch-size` строк, по умолчанию 100. Если Q не делится на размер пачки, последняя пачка короче. Одна пачка — это один запрос:

```sql
DECLARE $input AS List<Struct<...>>;
UPSERT INTO `<таблица>`
SELECT * FROM AS_TABLE($input);
```

Поля структуры называются так же, как колонки таблицы, и идут в том же порядке. Первичный ключ и `seqno` в структуре обязательны, остальные поля значений необязательны (`тип?`). Повтор пачки идемпотентен: он отправляет те же строки с теми же значениями, включая то же пустое поле.

Пачки одной таблицы отправляются по очереди, а разные таблицы обрабатываются одновременно. Число потоков задаёт `--threads`. По умолчанию оно равно числу vCPU текущего хоста. Одновременно обрабатывается меньшее из двух чисел: число потоков и число таблиц в каталоге.

Команда завершается после фиксации всех пачек. Размер пачки действует только на `import` и не влияет на размер транзакций `run`.

Если в таблицах уже есть строки, повторный `import` завершается ошибкой и данные не переписывает. Обычный порядок — один `import` после `init`.

При Q = 0 таблицы остаются пустыми. Первые транзакции `run` тогда состоят из вставок, пока в таблице не появится хотя бы одна зафиксированная строка.

## Граница номеров {#boundary}

Изменение обращается к уже существующей строке. Для этого у каждой таблицы есть граница: наибольший номер, вместе с которым зафиксированы и все меньшие номера. Существующие номера — это `0, 1, …, boundary`. Следующая вставка получает `boundary + 1`.

### Чтение границы на старте `run` {#boundary-read}

Перед первой транзакцией команда один раз читает из базы границу каждой таблицы. Чтение идёт онлайн-запросом только на чтение, без сериализуемой блокировки. Срок ожидания — не меньше 10 минут и не меньше `--timeout`. Запросы к разным таблицам выполняются параллельно.

У композитного ключа номер хранится в `seq`. Это таблицы `pk_bool`, `pk_int8`, `pk_uint8`, `pk_int16`, `pk_uint16`, `pk_date` и `pk_decimal_narrow`. Граница читается так:

```sql
SELECT seq FROM `<таблица>` ORDER BY seq DESC LIMIT 1
```

Найденное значение `seq` и есть максимальный номер. Пустой результат означает, что таблица пуста и границы нет.

Для `pk_bool` и `pk_decimal_narrow` команда дополнительно читает хеш, записанный при вставке:

```sql
SELECT seq, seqno_hash FROM `<таблица>`
```

При изменении строки в условие подставляется `seqno_hash` из этого чтения. У строки, записанной командой `import`, хеш равен хешу нуля.

У остальных таблиц ключ — это перемешивание или хеш номера. Число уже записанных строк совпадает с числом номеров `0 .. boundary`, поэтому граница читается так:

```sql
SELECT COUNT(*) FROM `<таблица>`
```

Если запрос вернул `C`, максимальный номер равен `C − 1`, а следующий свободный номер равен `C`. Ноль означает пустую таблицу. Так читается граница всех одноколоночных обычных таблиц, включая `pk_string` и `pk_utf8`, и всех широких таблиц.

Такое чтение верно, пока в таблице лежат только строки этой нагрузки и их номера образуют сплошной префикс `0 .. boundary`. Как этот префикс сохраняется, описано ниже.

### Ведение границы во время `run` {#boundary-maintain}

Граница хранится в памяти процесса и сдвигается вперёд, когда транзакция с новыми номерами успешно фиксируется.

Одновременно резервировать новые номера одной таблицы может не больше одной транзакции. Резерв хранится в памяти клиента, и через него назначаются следующие номера. Отдельной блокировки строки или партиции на сервере команда не берёт. Если транзакции нужны вставки в несколько таблиц, она берёт резерв в порядке имён таблиц и держит его до своего завершения. Из-за этого порядка пользователи не могут взаимно ждать друг друга. Повтор транзакции использует уже зарезервированные номера. Номер входит в границу только после успешной фиксации. До фиксации эти номера для изменения не выбираются.

Поэтому зафиксированные номера каждой таблицы всегда идут подряд от 0 до текущей границы. Следующий запуск `run` читает ту же границу тем же запросом: `ORDER BY seq DESC LIMIT 1` для композитного ключа и `COUNT(*)` для остальных таблиц. Если процесс останавливается до фиксации, сервер откатывает незавершённую транзакцию, и префикс номеров остаётся сплошным.

Номер для изменения выбирается равномерно среди `0 .. boundary` включительно, по границе на начало транзакции. В одной транзакции эти номера не повторяются, пока их не больше, чем `boundary + 1`. Если запланированных изменений больше, чем уже существующих строк, лишние изменения становятся вставками и получают следующие номера.

## Транзакции {#transactions}

Каждая транзакция — одна атомарная запись в сериализуемом режиме. Она вставляет новые строки и изменяет уже существующие. Удалений нет, состав колонок не меняется.

Число затронутых таблиц **M** выбирается равномерно от 1 до числа таблиц в каталоге. Затем равномерно выбирается случайное подмножество из M различных таблиц.

В каждую выбранную таблицу транзакция пишет **R** строк. Число R выбирается равномерно от 1 до **K** включительно. K задаётся параметром `--max-records`. Из этих R строк `floor(R / 2)` планируются как вставки, остальные — как изменения. При R = 1 это одно изменение. При R = 2 — одна вставка и одно изменение. Если существующих строк меньше, чем запланировано изменений, недостающие изменения выполняются как вставки. В пустой таблице все R строк — вставки.

Вставка заполняет все колонки и выполняется оператором `UPSERT`. С вероятностью 10% одно случайное поле значения этой строки, кроме `seqno`, равно `NULL`. Изменение каждой строки выполняется оператором `UPDATE` и задаёт новые значения у 1, 2 или 3 её колонок. Число колонок выбирается равномерно. В набор всегда входит `seqno` с номером операции этой транзакции. Остальные места занимают случайные колонки со значениями, не входящие в первичный ключ. С вероятностью 1% одно из этих присваиваемых значений, кроме `seqno`, равно `NULL`. Если в наборе нет других колонок, кроме `seqno`, пустое значение не записывается. Условие `WHERE` содержит все колонки первичного ключа и сравнивает каждую из них на равенство. Для одноколоночного ключа это `pk`, в широкой таблице — `id`. Для `pk_int8`, `pk_uint8`, `pk_int16`, `pk_uint16` и `pk_date` это `pk` и `seq`. Для `pk_bool` и `pk_decimal_narrow` это `seqno_hash`, `pk` и `seq`. В `seqno_hash` подставляется хеш, записанный при вставке строки.

Каждый оператор уходит отдельным запросом в одной интерактивной сериализуемой транзакции. Первый запрос открывает транзакцию, следующие её продолжают, а последний запрос её фиксирует: у него выставлен признак фиксации. Вся попытка выполняется штатным обработчиком повторов SDK с признаком идемпотентности. Статус запроса возвращается в этот обработчик. Если статус можно повторить, обработчик заново выполняет всю попытку.

Текст запроса — это объявления параметров и один оператор. Имя параметра совпадает с именем колонки. Все вставки в одну таблицу получают один и тот же текст: в нём перечислены все колонки. Текст изменения определяется таблицей и набором колонок в `SET`. Колонки этого набора перечисляются по имени, поэтому один набор даёт один текст. Пустое значение оставляет текст прежним: у колонки значения, кроме `seqno`, тип параметра всегда необязательный. Повтор одинакового текста позволяет серверу взять уже построенный план из кеша.

Транзакция идемпотентна. Клиент выполняет её в обработчике повторов с признаком идемпотентности. До первой попытки запоминаются первичные ключи, колонки для изменения, их новые значения и `seqno`. Каждая попытка заново открывает транзакцию и отправляет те же операторы отдельными запросами, с теми же параметрами. Если фиксация прошла, но клиент не получил ответ, повторный `UPSERT` записывает те же строки и не конфликтует по первичному ключу. Повторный `UPDATE` снова записывает те же колонки по тому же полному первичному ключу. Обработчик повторяет попытку для статусов, которые безопасно повторять у идемпотентной операции, в том числе когда результат попытки неизвестен. При повторе не выделяются новые номера строк, новый `seqno` и другой набор колонок.

Транзакция считается успешной после обработчика повторов. Повторяемые сбои не входят в частоту ошибок, если итоговая попытка успешна. Ошибкой считается транзакция, последняя попытка которой завершилась неуспехом. Одна такая транзакция — одна ошибка, сколько бы таблиц в ней ни было. Номера её строк в границу не входят, а её `seqno` больше не используется. Резерв номеров при этом снимается, и следующая вставка в ту же таблицу снова берёт номера начиная с `boundary + 1`.

## Параллелизм {#concurrency}

Параметр `--users` задаёт число параллельных пользователей. По умолчанию он равен 1. Каждый пользователь выполняет одну транзакцию, ждёт `--pause` и начинает следующую. Пауза одинакова после успеха и после ошибки и не останавливает остальных пользователей.

Одновременно выполняется не больше транзакций, чем задано пользователей. Пул сессий клиента рассчитан на это число. Если несколько транзакций вставляют строки в одну таблицу, они получают номера через её резерв по очереди. Транзакции с непересекающимися наборами таблиц идут одновременно. Изменение уже зафиксированных строк резерв номеров не занимает и очередь вставок не задерживает.

Параметр `--threads` задаёт число потоков клиентского пула, в которых завершаются асинхронные операции. По умолчанию он равен 0: пул адаптивный, его размер выбирает клиент. Положительное значение фиксирует размер пула. Число сетевых потоков драйвера остаётся клиентским значением по умолчанию.

Параметр `--seconds` ограничивает время запуска. Когда время истекло, новые транзакции не начинаются. Уже начатые дожидаются завершения: на каждый их запрос действует `--timeout`. Пользователь, который в этот момент ждёт `--pause`, новую транзакцию не начинает. Когда начатая транзакция завершается фиксацией или ошибкой, её резерв номеров снимается. Команда завершается, когда все начатые транзакции закончились.

Параметр `--seed` задаёт начальное значение генератора случайных чисел: от него зависят выбор таблиц, число строк R, выбор номеров для изменения, длины и содержимое значений. При нескольких пользователях зерно задаёт решения каждого из них, но не порядок, в котором их транзакции перемежаются. Если параметр не указан, зерно берётся из текущего времени. Номера новых строк от зерна не зависят: их назначает граница таблицы.

## Вывод {#output}

Раз в `--window` секунд, по умолчанию раз в секунду, на стандартный вывод печатается одна строка:

```text
elapsed_s=<секунды> tx_per_s=<частота> errors_per_s=<частота> tx=<число> errors=<число>
```

Поля `tx` и `errors` — счётчики за это окно. Частота равна счётчику, делённому на длину окна, и печатается с одним знаком после точки. `tx` считает зафиксированные транзакции: одна многооператорная транзакция даёт единицу, сколько бы операторов в ней ни было.

После остановки печатается итог за всё время запуска в той же форме. Поля `tx` и `errors` в нём суммарные, а частоты посчитаны по полной длительности.

С глобальным параметром `--verbose` (`-v`) каждая ошибка дополнительно печатается на стандартный вывод ошибок:

```text
error status=<код статуса> issues=<текст сообщений>
```

Текст запроса в это сообщение не входит. Без `--verbose` печатаются только частоты и счётчики.

Команда `run` завершается с ненулевым кодом, если её не удалось начать или если оборвалась сама команда: нет таблиц, неверные параметры или сбой при чтении границы. Ошибки отдельных транзакций код возврата не меняют. Они видны в `errors` и, при `--verbose`, в текстах ошибок.

## Параметры {#options}

Общие для `init`, `import`, `run` и `clean`:

| Параметр | Описание | По умолчанию |
| --- | --- | --- |
| `--path` | Каталог таблиц нагрузки в базе-источнике | `replication` |

`init`:

| Параметр | Описание | По умолчанию |
| --- | --- | --- |
| `--min-partitions` | Минимум партиций таблицы и каждого вторичного индекса, `AUTO_PARTITIONING_MIN_PARTITIONS_COUNT` | `1000` |
| `--max-partitions` | Максимум партиций таблицы и каждого вторичного индекса, `AUTO_PARTITIONING_MAX_PARTITIONS_COUNT` | `1100` |

`import`:

| Параметр | Описание | По умолчанию |
| --- | --- | --- |
| `--rows` | Q, число строк начального заполнения в каждую таблицу | `1000` |
| `--batch-size` | Число строк в одном запросе `UPSERT … SELECT * FROM AS_TABLE` | `100` |
| `--threads` | Потоки, которые отправляют пачки. По умолчанию — число vCPU текущего хоста | число vCPU |

`run`:

| Параметр | Описание | По умолчанию |
| --- | --- | --- |
| `--seconds`, `-s` | Длительность записи, секунды | `60` |
| `--users` | Число параллельных пользователей | `1` |
| `--max-records` | K, верхняя граница числа строк в одну таблицу внутри транзакции. Фактическое число случайно от 1 до K | `10` |
| `--pause` | Пауза пользователя между транзакциями. Число без суффикса задаёт миллисекунды | `100ms` |
| `--threads` | Потоки клиентского пула. 0 — адаптивный пул | `0` |
| `--window` | Окно вывода частот, секунды | `1` |
| `--seed` | Зерно генератора. Без параметра зерно берётся из текущего времени | — |
| `--timeout` | Таймаут каждого запроса. Последний оператор транзакции в том же запросе её фиксирует. Число без суффикса задаёт миллисекунды | `10s` |

У запроса к сервису запросов один клиентский таймаут, и команда `run` задаёт его параметром `--timeout`. Срок относится к одному запросу, в том числе к последнему оператору, который в том же запросе фиксирует транзакцию, и в том числе когда строка занимает несколько килобайт. Транзакция из нескольких операторов может занять несколько таких сроков. Начальное чтение границы использует отдельный, более длинный срок: см. раздел [границы номеров](#boundary-read).

## Пример {#example}

```bash
{{ ydb-cli }} workload replication init --path replication
{{ ydb-cli }} workload replication import --path replication --rows 1000
```

Затем в базе-приёмнике пользователь создаёт экземпляр репликации. Краткий пример запроса приведён [ниже](#create-replication). Команда нагрузки этот запрос не выполняет.

После создания экземпляра можно запустить запись. С параметром `-v` тексты ошибок выводятся на стандартный вывод ошибок:

```bash
{{ ydb-cli }} -v workload replication run \
    --path replication \
    --users 4 \
    --max-records 10 \
    --pause 100ms \
    --seconds 300
```

Удаление таблиц:

```bash
{{ ydb-cli }} workload replication clean --path replication
```

## Пример создания асинхронной репликации {#create-replication}

Запросы из этого раздела выполняются в базе-приёмнике после команды `import` и до команды `run`. Команда нагрузки их не выполняет.

Сначала в базе-приёмнике создаётся [секрет](../../yql/reference/syntax/create-secret.md) с паролем пользователя базы-источника:

```yql
CREATE SECRET source_password WITH (value = "<пароль>");
```

Затем создаётся экземпляр репликации для каталога `replication`. Одна пара путей охватывает все таблицы этого каталога, путь на приёмнике совпадает с путём на источнике. Для аутентификации указываются логин в параметре `USER` и секрет с паролем в `PASSWORD_SECRET_PATH`. Соединение устанавливается по `grpcs://`. Корневой сертификат источника передаётся в `CA_CERT` как сырая строка `@@…@@`. Параметр `CONSISTENCY_LEVEL = 'ROW'` задаёт [согласованность уровня строки](../../concepts/async-replication.md#consistency-level-row). Это значение используется по умолчанию.

```yql
CREATE ASYNC REPLICATION source_repl FOR `replication` AS `replication`
WITH (
    FORMAT = 'BINARY',
    USER = 'test1',
    PASSWORD_SECRET_PATH = 'source_password',
    CONSISTENCY_LEVEL = 'ROW',
    CONNECTION_STRING = 'grpcs://localhost:2135/?database=/Root/source',
    CA_CERT = @@
-----BEGIN CERTIFICATE-----
...
-----END CERTIFICATE-----
    @@
);
```

Остальные параметры соединения и аутентификации описаны в [CREATE ASYNC REPLICATION](../../yql/reference/syntax/create-async-replication.md).

## Что остаётся пользователю {#scope}

Пользователь сам создаёт экземпляр асинхронной репликации, смотрит его состояние, останавливает и удаляет. Команда не ждёт окончания первоначального сканирования и не читает лаг. Она также не проверяет, совпадает ли реплика с источником.
